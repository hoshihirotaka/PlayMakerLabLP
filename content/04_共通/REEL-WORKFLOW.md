# リール制作ワークフロー（動画 → テロップ → 投稿文）

撮影済みの動画を渡されてから、SRTとキャプションを作るまでの手順。
セクション1〜3・OBBY講座の4本で確立した流れ。

- 個別のリールの記録 → [reels/](../03_定期投稿/sns/reels/)
- SNS共通ルール → [SNS-GUIDE.md](SNS-GUIDE.md)

---

## 前提：先に動画、あとからテロップ

**構成を先に決めない。** 撮りやすい形で撮ってもらい、できた動画から読み取ってテロップを作る。
撮影の自由度を制約するより、解析で拾うほうが良い動画になる。

渡されたときに「どのギミックが出るか」「ゴール到達の有無」を一言もらえると精度が上がるが、なくても解析できる。

---

## 回ごとのコンセプトを先に決める（最重要・育てていく定義）

**2026-08-21 新設。** 型（3つのライン）が回るようになった次の段階として置く。
**ここは今後も改善していく定義**で、計測のたびに書き換える前提。

3つのライン（→ 後述）は**フォーマットの分類**であって、
「誰に・何を証明するか」が入っていない。**それを回ごとに決めるのがこの節。**

構成そのものは先に決めない（前提のとおり）。決めるのは**中身の狙い**で、
遅くとも**テロップを書く前**には固めておく。

### 決める4項目

| 項目 | 選択肢 |
|---|---|
| **誰に** | 保護者（父／母）／中高生本人／**すでに来た保護者** |
| **何を証明するか** | ゲームの作り方（企画・設計）を教える／**作り続けている講師**／Roblox＋AIの両方／作って終わりにしない |
| **時限性** | 使い捨て（日付あり）／**資産（日付なし）** |
| **成功指標** | 国内リーチ／保護者リーチ／保存／**既存客の反応** |

「何を証明するか」の選択肢は、[AGENTS.md](../../AGENTS.md) の核心となる思想から取っている。
**投稿の目的は作品を見せることではなく、この4つのどれかを証明すること。**

### 決めないと何が起きるか（実例）

**① USPが載らない**

ドロー＆ドライブの冒頭テロップは「**これ、AIに作ってもらったゲームです**」だった。
AI製であることは言っているが、**「誰が」が抜けている**。これでは
「AIで作ったゲームの紹介」であって、教室の投稿にならない。

3D忍者スライドでは「**先生がAIで作ったパズル**」に直した。
**たった3文字だが、USPが載るか載らないかの差**になる。

**② 資産にすべきものが使い捨てになる**

| | 補充可能性 | 日付を入れるか |
|---|---|---|
| **参加者の作品** | **掲載許諾が燃料。回ごとにしか増えない希少資産** | **入れない** |
| 講師の作品 | 思いついた日に作れる。在庫が効く | どちらでも |
| 開催告知 | いくらでも作れる | 入れる（それが役割） |

**参加者の作品にテロップで日付を入れない。** 開催日を過ぎた瞬間に、
ハイライトに入れられず、再利用もできず、**作った本人の保護者に見せることもしにくくなる**。

来場した保護者がいちばん反応してくれるのが参加者の作品なので、
**ここを最初に腐らせるのは損失が大きい**。日付はキャプションに書けば足りる。

（2026-08-21時点で、日付入りは参加者の作品2本だけという逆転が起きていた。以後は入れない）

## 手順

### 1. 尺と解像度を確認

```bash
ffprobe -v error -show_entries format=duration \
  -show_entries stream=codec_type,width,height \
  -of default=noprint_wrappers=1 "動画.mp4"
```

ffmpeg は `/usr/local/bin/ffmpeg` にある（PATHから拾えないことがあるのでフルパス推奨）。

### 2. 静止区間を測る（最重要）

1秒ごとにフレームを抜き、隣接フレームの差分を取る。

```python
from PIL import Image, ImageChops
import glob
fs = sorted(glob.glob("frames/*.png"))
prev = None
for i, p in enumerate(fs):
    im = Image.open(p).convert("L")
    if prev is not None:
        d = ImageChops.difference(im, prev)
        print(i, sum(d.getdata()) / (im.width * im.height))
    prev = im
```

フレーム抽出は `ffmpeg -i 動画 -vf "fps=1,scale=180:-1" frames/%03d.png`。

**変化量が1.0未満の区間が「静止」。** ここが長いとリールでは致命的なので、必ず測って報告する。

### 3. 構成を把握する

コンタクトシートで全体を見る。

```bash
ffmpeg -i 動画 -vf "fps=1/3,scale=250:-1,tile=5x4" -frames:v 1 sheet.png
```

細部（メニュー名・スクリプトの中身）を読みたいときは、該当秒を切り出して拡大する。

```bash
ffmpeg -ss 30 -i 動画 -frames:v 1 -vf "crop=1080:1100:0:800,scale=400:-1" f30.png
```

### 3-b. 画面に焼き込まれている文字を棚卸しする（2026-09-07 追加）

**カット割りだけ見てテロップを設計すると、映像に入っている文字と重複する。**

2026-09-07に実際にやった。末尾のバナーに「今月のお題」「スピードアップのスクリプト実装」
「3回とも同じお題です」が印刷されていて、**テロップがほぼ同じことを言っていた。**
位置も重なっていた。

```
測ったもの   静止区間・尺・カット割り
測っていなかったもの   画面に何が書いてあるか
```

**看板・バナー・教材のスクショ・Studioの画面──文字が入る素材は多い。**
テロップを書く前に、**その文字を書き出す。** コンタクトシートで読めなければ拡大する。

**とくに末尾に情報カード（バナー）を置く回は、カードの細かい文字まで読むこと。**

### 4. SRTを作る

**静止区間には必ずテロップを乗せる。** 画面が止まっている間はテロップが唯一の情報源になるので、
ラベルではなく中身のある文にする。生成後、静止区間がカバーされているか検算する。

### 4-b. 書き出し後、実物のテロップでSRTを上書きする

編集ソフト側で文言を調整するため、手順4のSRTは**投稿される実物とズレる**。
CapCutの字幕書き出しは**有料**なので、書き出した動画から読み取って復元する。

```bash
# 字幕帯だけを切り出してコンタクトシート化 → 目視で書き起こす
/usr/local/bin/ffmpeg -i 書き出した.mov \
  -vf "fps=1,crop=1080:520:0:1180,scale=430:-1,tile=4x8" -frames:v 1 tel.png
```

- `crop=幅:高さ:X:Y`。`1080:520:0:1180` は「上から1180pxの位置から高さ520px」。
  テロップ位置が違う回はYを調整する
- **1秒1コマなので、同じ文言が続く枚数がそのまま表示秒数**になる
- これをやらないとリポジトリのSRTが実物と食い違い、記録として使えなくなる

**ファイル名は版ごとに変える。** CapCutは同じ名前のSRTを再インポートできない。
`{スラッグ}-v1-draft.srt` → `-v2-revised.srt` → `-v3-final.srt` のように残す（[reels/README.md](../03_定期投稿/sns/reels/README.md)）。
最終版だけ残すのではなく初稿も置いておくと、**「提案 → 実際に採用された文言」の差分が次の設計材料になる**。

### 5. キャプションを作る

タグ5個・本文500文字以内（Threads同時投稿の制約）。詳細は [SNS-GUIDE.md](SNS-GUIDE.md)。

## ffmpegとCapCutの分担（2026-09-07 確立）

**GUI操作に頼る部分を最小にする。**

```
ffmpeg   カット・パン・ズーム・重ね・連結・尺合わせ・静止区間の検算
CapCut   テロップ／絵文字／音
```

**組み立てをスクリプトにしておくと、素材を差し替えて何度でも作り直せる。**
実例 → [reels/2026-09-07-tsukuru-gawa/組み立て.sh](../03_定期投稿/sns/reels/2026-09-07-tsukuru-gawa/組み立て.sh)

冒頭で素材のパスを変数にしておき、末尾で静止区間の検算まで走らせる。
**「作り直す」が数十秒で終わるので、構成の試行錯誤ができる。**

### 素材を使い回すときに確認する3つ

| | |
|---|---|
| **比率** | 横位置（16:9）の素材は9:16に**3割ほどしか入らない**。構図が持つ秒を探す |
| **焼き込み** | 完成品にはテロップが焼かれている。**日付が入っているものは使えない** |
| **許諾** | 参加者の作品・人物は**回ごと**。「前の回でOK」は次の回をカバーしない |

**⚠️ クロップ自体が目隠しになる。** 縦画面に横写真を入れると3割しか映らないので、
**写したくない人を範囲外に置ける。** 絵文字やぼかしの前に、まず切り取る位置で解決できないか見る。

## 画面収録を縦リールにする（2026-09-10 確立）

**撮り方で決まる。編集では取り返せない。**

### 横1920で撮ると詰む

パソコンの画面（1920×1080）をそのまま撮ると、9:16に切り出しても
**文字の拡大率は1.15倍にしかならない。** パソコンで普通に読める文字が、
スマホでほぼそのままの小ささで出る。親指で流し見される場所なので、これは致命的。

2026-09-10、この理由で**5分09秒と4分37秒の素材を捨てて撮り直した。**

### 撮影条件

| | |
|---|---|
| **窓の形** | ブラウザの窓を**横1080px・縦は画面いっぱい**の、正方形に近い形にする |
| **拡大率** | ページを**175%**（Cmd と + を4回） |
| **収録範囲** | **ウインドウ収録**（Cmd+Shift+5 → ウインドウ）。デスクトップもドックも入らない |
| **音声** | 不要。テロップで運ぶ |

切り出しが等倍で済み、**文字は1.75倍**になる。拡大による滲みも出ない。

### 撮影前に消しておくもの

**あとで隠すより、撮る前に消すほうが速い。**

| | |
|---|---|
| タブ | **1枚だけ**にする。2026-09-10、受信トレイのタブに教室のアドレスが出ていた |
| ブックマークバー | `Cmd+Shift+B` |
| 通知 | おやすみモード |
| メール | 受信トレイの一覧を映さない。**テスト用を1通用意して、それだけ開く** |
| カレンダー | テスト用の予定だけ入れた週を映す |

### 組み立て

```
上から120px   ブラウザのタブとURL欄。切り落とす（タブ名の映り込みもここで消える）
1080×1036    中身。1080×1920 の y=150 に置く
y=1200       テロップ（PNGで作って重ねる）
y=1440 以下   空けておく。ブーストのCTAボタンが来る帯
```

**⚠️ 可変フレームレートに注意。** 画面収録はVFRなので、`trim` と `setpts` で速度を変えると
**尺の計算が合わない。** 先に `fps=30` を通してCFRに直してから切る。
2026-09-10、これを飛ばして51.5秒のはずが46.9秒になった。

### 待ち時間は測って詰める

生成待ちとタイピングで、**画面収録は8割が止まっている。**
`freezedetect` は打鍵まで「停止」と判定するので、差分で測る。

```bash
ffmpeg -v info -i 収録.mov -vf "fps=2,scale=240:-1,tblend=all_mode=difference,signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=-" -f null -
```

2026-09-10の実測では142秒のうち約100秒、79秒のうち約60秒が動いていなかった。
**1.4〜6倍速で詰めて、素材254秒を82秒にした。**

## 実用系（ハウツー）の構成の型（2026-09-10 本人案）

**作品紹介とは別の型。** 作品紹介はプレイ映像が主役で結末を見せるが、
実用系は**見る人の困りごとから入る**。

```
① こんなことに困っていませんか   ← モヤっとさせる。ここが要
② 実は解決できます              ← 「あなたが悪いわけじゃない」を挟む
③ 操作説明                      ← 通常速度、またはやや遅く
④ 忘れないように保存して、試してみてね
```

### 題材には2つの軸がある。構成が変わる

**「作業が大変」でひとくくりにしない。** 大変さの種類で効く構成が違う。

| 軸 | 感情 | 例 | 効く型 |
|---|---|---|---|
| **こわさ** | 見落としたらどうしよう | メール・カレンダー・アジェンダ・投稿の見直し | **上の4段構成** |
| **面倒／できない** | やりたいが時間がない、作れない | 図と矢印・下書き・調べもの | **ビフォーアフター型** |

**恐怖は放っておくと毎日じわじわ効く。面倒は、諦めれば消える。**
図が作れなければ図なしで出せばいいが、メールの見落としは諦めても不安が残る。
**恐怖のほうが強い題材になる。ただし数は少ない。**

②の「自分を責めないで」は**こわさ系にしか要らない。**
図が作れないことで自分を責めている人はいないので、面倒系に入れると回りくどくなる。
面倒系は「これ、5分です」で終わってよい（→「保存されるもの／されないもの」のビフォーアフター型）。

### 手法から入らない

**2026-09-10、同じ形の間違いが1日に3回出た。**

| 手法（刺さらない） | 困りごと（刺さる） |
|---|---|
| 話しかけるだけで予定が入る | 予定を手で転記している |
| AIで図と矢印を作る | 資料を作る時間がない |
| メールを要約する | 見落としていないか怖い |

**「AIで◯◯したい」と思っている人はいない。「◯◯が面倒だ」と思っている人がいる。**
題材を思いついたら、**それが手法か困りごとかを一度確認する。**
手法のまま冒頭に置くと、すでに欲しい人にしか届かない。

### ① が全部を決める

2026-09-10のリールは「話しかけるだけで予定が入る」で始めた。**これは能力の提示で、
すでに欲しいと思っている人にしか届かない。** まだ欲しいと思っていない人を止めるには、
自分の困りごととして認識させる必要がある。

**題材は「機能」ではなく「いま手でやっている面倒」から選ぶ。**

### ② に「自分を責めないで」を入れる理由

大人向けAI講座の参加者は**AIの設定で止まっているリテラシー層**。
設定で止まっている人は「自分ができないだけ」と思っている。
**そこを外さないと、③の操作説明が「自分には無理な話」として流れる。**

### ③ の速度は役割で分ける

| 見せているもの | 速度 |
|---|---|
| こういうことができる（結果を見せる） | 速くてよい |
| ここを押す（手順を真似させる） | **等速か、やや遅く** |

2026-09-10は入力の場面に6倍速をかけた。**結果を見せるには十分だが、
手順として真似したい人には速すぎた。** 1本の中で混ぜない。

### ④ 保存の呼びかけは営業ではない

2026-09-10、営業文言を全部落とす方針にしたら、**保存の呼びかけまで落ちて保存がゼロになった。**
「ノウハウまとめ型」は本来もっとも保存されやすい型なのに、一度も頼まなかった。

**申込への誘導を置かない回でも、保存の一言だけは残す。**

## 静止画・カードを動画に入れる型（2026-09-07 確立）

告知カードや日程表を混ぜると、そこだけ止まる。**3つ守れば成立する。**

### ① 動く映像に重ねる。ゆっくりズームでは足りない

**静止画にKen Burns（ゆっくりズーム）をかけても、静止区間として検出される。**
1080×1350のカードを9:16に置くと**上下に帯が出て、そこが画面の3割を占めて動かない**ため。

**ぼかした映像の上にカードを重ねる。** 背景が動くので止まらない。

### ② カードは上詰めにする

```
中央寄せ  カード下端が広告のCTAボタンと重なる
上詰め    ボタンはカードの下に来る。重ならない
```

**上詰めにすると、背景が見えるのは下の帯だけになる。**
そこに顔が入らない素材を選べば、**ぼかしも要らなくなる**（動きも見える）。

### ③ 固定カメラの素材は、そのままでは動かない

引きの定点映像は雰囲気が良いが、**フレーム間の差がほぼゼロ**。
**背景を2割ほど大きくしてから、時間でクロップ位置を動かす**（ゆっくりパン）。

## 分かったこと（2026-08-13 の計測で更新）

### 効いたこと

- **日本語テロップ＋日本語タグ＋地域タグで、視聴者のほとんどが日本になった。**
  Robloxの画面は言語シグナルがほぼゼロなので、**日本語をどこかに出すことが要る。**
  **⚠️ 2026-09-07訂正: 「画面内に」と書いていたが、キャプションでも効く。**
  **→ 上の「言語シグナルはテロップとキャプションの両方」を読む**
  テロップが薄い回だけ、視聴者の約半分が海外だった。
  **※ これは失敗ではなく、目的によって使い分ける設計変数。下記「言語の使い分け」を参照**
- **13〜17歳に届く。** Google広告は18歳未満に配信できないため、中高生本人に届くのはリールとMeta広告だけ。
  **リールは実際に届いていることが計測で確認できた**
- **フォロワー数はリーチの制約にならない。** リーチのほとんどがフォロワー外
- **告知型は保護者層に届き、リーチも伸びる。** 教材解説型より保護者比率が明確に高く、シェアも唯一発生した

### 効かなかったこと

- **スライドで始めると冒頭で大半が離脱する。** スキップ率が複数本でほぼ同一だったので構造的な原因。
  タイトルカードは情報量ゼロで、しかも止まっている
- **尺を伸ばしても見られない。** 90秒台の回は、平均再生時間が58秒の回と変わらなかった。
  **平均再生時間は内容が違っても横並びになる**ため、尺を伸ばすほど維持率だけが下がる
- 保存・シェア・コメントは維持率の帰結。最後まで見ていない人は保存しない。**順番として、まず冒頭**

## 言語シグナルはテロップとキャプションの両方（2026-09-07 訂正）

**以前ここには「画面内に日本語を出すことが決定的」と書いていた。不正確だった。**
**キャプションの語彙も配信先を決める。**

### 変数を1つだけ変えた観測

```
動画    テロップなし（教室の風景）→ 画面に言語シグナルがない
最初    キャプションに「Roblox」（ラテン文字）  → 海外に配信された
編集    「AI講座」に書き換え                    → 日本からの閲覧が増えた
```

**動画は一切変えていない。キャプションの語彙だけで配信先が動いた。**

### 効く順番

| | |
|---|---|
| **テロップがある動画** | 画面の日本語が強く効く。キャプションは補助 |
| **テロップがない動画** | **キャプションが決定的になる。**ラテン文字を書くと海外へ振れる |

**風景・作品・プレイ映像だけの回はテロップがゼロになりやすい。**
そういう回ほど、**キャプションとタグの表記を日本語に寄せる。**

### 【仮説・未検証】配信は2段階で決まっているのではないか（2026-09-07）

**⚠️ これは確定ではない。打ち手は変わらないので、急いで確かめる必要もない。**
**効いてくるのは「うまくいかなかったときに、どこを直すか」の切り分け。**

```
① 初期配信の決定    キャプション・タグ・音声・映像から「誰に見せるか」を推定
② 反応による絞り込み  見た人が残ったか離脱したかで、似た人への配信を増減
```

| | 効く段階 | 役割 |
|---|---|---|
| **キャプション・タグ** | ① | **攻め。**どこに出すか |
| **テロップ** | ② | **守り。**日本語だと海外の人が離脱し、そちらへの配信が減る |

**これまでの観測を全部説明できる。**

- テロップなし＋キャプションがラテン文字 → ①で海外へ。
  **Roblox映像は言語障壁が低いので離脱もせず**、②でも削られなかった
- キャプションを日本語に変えたら①が動き、日本からの閲覧が増えた
- 「テロップが薄い回だけ半分海外だった」も、**②が働かなかった**と読める

#### 確かめられていない理由

**日本語テロップ・日本語タグ・地域タグを同時に変えた回しかない。** ①と②を分離できていない。
分けるには、**片方だけ変えた回**が要る。

#### 調べるとしたら

**インサイトの地域別×維持率。** 海外の視聴者が冒頭で落ちているなら②の裏が取れる。
数値なので `~/curriculum/運営/リールインサイト/`（PRIVATE）側の作業。

#### 派生案：後から絞り込ませる運用（2026-09-07 本人の着想）

**「最初は広く配信させて、あとで絞る」ができるのではないか、という案。**

**⚠️ 動画の差し替えはできない。** Instagramは公開後に**動画そのものを入れ替えられない**
（編集できるのはキャプション・タグ・位置情報など）。**やるならキャプションだけ。**

**そして本人が同時に指摘したとおり、逆効果になりうる。**

```
最初に海外へ広く配信される  →  そのリーチは申込につながらない
初速の反応が悪いと          →  全体の配信そのものが伸びなくなる可能性
```

**「広く出してから絞る」より「最初から狙って出す」ほうが安全。**
**この案は採らない。** ただし、**海外比率が高いと気づいたときの後追い修正としては有効**
（実際に効いた実績がある）。

### 実務

- **国内に届けたい回では、ラテン文字の `Roblox` を本文とタグに書かない。**
  `ロブロックス` を使う。タグも `#Roblox` ではなく `#ロブロックス`
- **`#Roblox` と `#ロブロックス` を並べない。** 同じ概念に5枠のうち2つ使うことになる
- **投稿後でも直せる。** キャプションを編集すれば配信は変わる。
  **海外比率が高いと気づいたら、その場で書き換える**

## 言語の使い分け（2026-08-19 方針）

**「日本語テロップは常に必須」ではない。作品の性質で目的が変わり、正解も変わる。**

| 作品の種類 | 目的 | テロップ | 届けたい相手 |
|---|---|---|---|
| **体験会の作品・教材解説・開催告知** | **集客** | **日本語を厚く入れる** | 国内・保護者 |
| **常連が作り込んだ作品** | **PR・実績** | **薄くてよい（海外に出す）** | 世界・Roblox層 |

### なぜ分けるか

体験会の作品は「**1回でここまで作れる**」という入口の証明なので、国内に届けば十分。
申込に繋がらない海外リーチはコストにしかならない。

一方、常連が作り込んだ作品は「**続けるとここまで行く**」という到達点の証明。
Robloxは世界のプラットフォームで、作品は誰でも遊べる。**海外に届くことがそのまま価値になる。**

### ただし素材がまだない

作品ギャラリーの掲載分は**すべて体験会の作品**。「常連が作り込んだ作品」はまだ出ていない。
この施策は**継続の子が作品を完成させて初めて成立する**。

```
継続的に通う子が増える → 作り込んだ作品ができる → 世界向けPR
```

先に**講師自身の作品で型を作っておく**と、素材ができたときにすぐ載せられる（掲載許諾も不要）。

### ハイライトは目的別に分ける

プロフィールに置くなら2本立てにする。**混ぜると両方中途半端になる。**

| ハイライト | リンク先 | 役割 |
|---|---|---|
| 作品 | DreamCore など作品そのもの | 信頼・PR |
| 次回開催 | Doorkeeper | 申込 |

作品側に飛ばした人は申込ページから遠ざかるため、導線を分けておく。
リール視聴者の一定数がプロフィールを踏むので（比率は `~/curriculum` 側）、そこに両方置く意味がある。
リンクステッカーの扱いは [SNS-GUIDE.md](SNS-GUIDE.md) を参照。

### 海外に出すときの確認事項

子どもの作品を海外まで届ける段になったら、**掲載許諾の範囲**を確認しておく。

利用規約は「教育・広報目的で成果物を紹介させていただく場合があります」で表現としては広いが、
保護者が「教室のサイトに載る」と思って同意したものが世界規模で広がるのは、感覚として別物。
**アンケートQ8の文言に「SNSでの紹介（国内外）」のように範囲を明示しておく**と、後で気まずくならない。

## 保存されるもの／されないもの（2026-08-21 追記）

保存はこれまで**ほぼ発生していない**。作品紹介・講座シリーズのどちらでも起きていない。
調べたところ、**コンテンツの型で決まる**ことが分かった。

### 一般に保存される5つの型

| 型 | 中身 |
|---|---|
| ノウハウまとめ型 | 「○○のやり方」「失敗しないポイント」。最も保存率が高いとされる |
| チェックリスト型 | 確認事項を箇条書き。あとから見返す価値が生まれる |
| テンプレート型 | そのまま使える実物 |
| ビフォーアフター型 | 変化を視認化 |
| まとめスライド型 | 1枚に情報が整理されている |

保存の心理は「**後で見返したい**」「一度では理解しきれない」「実用性が高い」。

### 保存されない型

> 日常の出来事や単なる感想だけの投稿は、その場で消費されてしまい、保存につながりにくい

**作品紹介はここに近い。** 「見て終わり」の構造なので、保存されないのは仕組み上の帰結。
**作品紹介で保存を取りにいくのは筋が悪い。**

### この事業に当てはめると

保存されるのは**保護者の意思決定に使える情報**。習い事の判断は
「**どこにするか**」と「**失敗したくない**」の2つなので、そこに効くものが保存される。

| 型 | 作れるもの |
|---|---|
| ノウハウまとめ | **Robloxを子どもにやらせる前に、親が確認すべき設定**（課金・チャット・知らない人との交流） |
| チェックリスト | 体験会の持ち物リスト |
| ビフォーアフター | 同じ子の1回目→3回目の作品（要・掲載許諾） |
| テンプレート | 子どもが実際に書いたプロンプト全文 |

**これは3つのラインのどれでもない、4本目のライン**（保護者向けお役立ち情報）になる。
既存ラインの改善ではなく、**本数配分に手を入れる話**。

### ただし優先度は要検討

保存は**一方通行**で、誰が保存したかは見えず、こちらから話しかけることもできない。
同じ「**逃さない**」心理に効くもので、**双方向にできるもの（公式LINEなど）のほうが上位互換**。
そちらが使える状態になったら、保存率の改善に割く労力の優先度は下がる。

## 制作チェックリスト（次の1本を作る前に）

上の学びを作業手順に落としたもの。**6項目すべてに○が付く状態で書き出す。**

- [ ] **回ごとのコンセプト4項目を決めた**（誰に／何を証明するか／時限性／成功指標）。
      → [回ごとのコンセプトを先に決める](#回ごとのコンセプトを先に決める最重要育てていく定義)。
      **参加者の作品なら、テロップに日付を入れない**
- [ ] **タイトルカードを入れていない。** 0秒目から画面が動いている
- [ ] **冒頭1〜2秒に、大きな日本語テキストがある。**（集客目的の回のみ）
      国内配信の担保とフックを兼ねる。プレイ映像主体の回ほど効く。
      **海外へ出す作品PRの回は、あえて薄くする**（上記「言語の使い分け」）
- [ ] **尺が30秒以内。** 超えるなら、後半を別の1本に割る
- [ ] **静止区間がゼロ**（手順2の差分測定で検算済み）
- [ ] **テロップが画面下から3割に入っていない。**
      **オーガニックでもユーザー名・キャプションで隠れ、広告ではCTAボタンが重なる。**
      2026-09-06のリールで実際に「詳細を見る」がテロップを踏んだ。
      **ブーストするなら、支払う前に設定画面のプレビューで実物を見る**
- [ ] **末尾に1アクションがある。** 「保存して持ち物チェックに」「日程はプロフィールから」など。
      保存とフォローには理由が要る

### 冒頭の作り方

タイトルカードの代わりに、**いちばん面白い瞬間を先頭に持ってくる**。

```
❌ タイトルカード → 説明 → 実演 → 結果
✅ 結果（いちばん動く瞬間）→ 「これ、10分で作れます」→ 実演
```

説明は「見る理由」が成立してから。順番を入れ替えるだけで、撮り直しは要らないことが多い。

## 3つのライン

| | 役割 | 届く相手 | 型 |
|---|---|---|---|
| 講座シリーズ | 流れを知ってもらう | 中高生本人が多い | 上部にスライド＋下部に実演。指示型のテロップ（「〜してみよう」） |
| 作品・ギミック紹介 | リーチを取る | 中高生本人が多い | プレイ映像が主役。短尺・静止なし・結末あり |
| **開催告知** | **申込につなげる** | **保護者が多い** | **テキスト主体。日付・会場・対象を画面に出す** |

**役割が違うので指標も分けて見る。** 講座シリーズは維持率が低くても、残った層が真剣に見ている。

**この表はフォーマットの分類。** 「誰に・何を証明するか」は
→ [回ごとのコンセプトを先に決める](#回ごとのコンセプトを先に決める最重要育てていく定義)

> **訂正（2026-08-21）**: 講座シリーズを「**検索・保存される資産**」と書いていたが、**反証された**。
> セクション1〜3はいずれも保存されていない。**基本操作は保護者の意思決定に使えない**ため、
> 保存の動機にならない。保存されるのは操作手順ではなく**判断材料**。

### 本数配分の考え方

現在の申込動線は保護者経由なので、**短期の集客を取りにいくなら告知型を厚くする**。
教材解説型・作品紹介型は中高生本人への種まきで、効いてくるのは先。両方必要だが、
「今月の参加者を増やしたい」ときに増やすべきは**告知型**。

### 現時点で最良の型（OBBY講座・36秒）

```
タイトルカードなし。0秒目から画面が動いている
静止ゼロ
「コードを見せる → 実際に動く」の往復
ゴール到達という結末がある
全部見せきらず「まだ他にもギミックが潜んでいます」で引きを残す
```

※ ただしこの回は画面内の日本語が薄く、視聴者の約半分が海外だった。
　 **この型を使うときは、冒頭の日本語テロップを必ず足す。**
